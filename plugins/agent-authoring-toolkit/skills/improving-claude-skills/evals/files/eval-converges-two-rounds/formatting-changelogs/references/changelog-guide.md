# Changelog grouping and ordering

Group unreleased entries by change type, using these groups in this order:

1. **Added** — new features.
2. **Changed** — changes to existing behavior.
3. **Fixed** — bug fixes.
4. **Removed** — removed features.

Omit a group with no entries. Within a group, keep the entries in the order they were written —
the changelog records history, not importance.

Every entry is one sentence, starts with a capital letter, and names the user-visible effect
rather than the implementation.
